# DeviceBridge workspace rules

- Read `prgress.md` first, then `docs/IMPLEMENTATION_STATUS.md`. Read the complete v4 specification before changing architecture. Later user instructions supersede it: **the laptop repository is authoritative**, per the 2026-11-18 correction. Phone copies are disposable build/test snapshots.
- At every session start inspect `.devicebridge-agent-session.lock`. Never overwrite an unresolved/live owner. Atomically create JSON with `agent_name`, `agent_id`, `chat_session_id`, `chat_path`, `project_path`, `created_utc`; preserve original pointers on takeover. Keep it out of Git. The lock identifies an active owner or a session interrupted before its handoff is complete. Remove it once a requested handoff is fully written, even when implementation is unfinished or changes are uncommitted; a commit is not a prerequisite for releasing a completed handoff. Preserve session/chat pointers in the handoff or an ignored archived record. Retain it when the handoff itself is incomplete. Keep `prgress.md` concise with current work, exact next commands, test evidence, gates and process ownership. Update before expensive work and before limits.
- Build functioning milestones M0, M1, M2 before broader features. Keep `docs/IMPLEMENTATION_STATUS.md` truthful; loopback, physical Android CLI, Waydroid, GUI and hardware acceptance are separate evidence levels.
- Phone: `ssh -p 8022 afzl@10.100.102.33`, known host key already present. Use explicit `bash -s` or `python` because the login shell is fish. Do not modify unrelated projects. Do not copy SSH keys, system credentials or private app state.
- **Standing user authorization (2026-11-18): all read-only and safely reversible work on Android and Linux is authorized.** Proceed with routine app installs/updates, bounded app testing, temporary scoped firewall/ADB setup and local Git commits without repeated confirmation when safely reversible. Prefer isolated DeviceBridge paths; preserve unrelated projects, sessions and existing configurations. Record changes and cleanup. This supersedes the v4 approval requirements within that scope. Irreversible/destructive changes and protected phone system changes remain forbidden or need separate explicit authority as applicable. Use no root for compilation; privileged diagnostics must stay scoped to authorized work.
- **Phone has temporary root and AVB protection. Never modify system files or partitions, raw block devices, boot/init_boot images, AVB/verity, bootloader, root modules or SELinux state. Never remount system partitions writable. These changes can soft-brick the phone. Development and testing stay unprivileged in DeviceBridge-owned directories; temporary root is not authorization.**
- Tailscale & WireGuard preference: laptops use the existing system tailscaled by default without reconfiguration or copied keys; Android uses an app-private tsnet node without VPNService (desktop tsnet is an explicitly enabled fallback only; real login requires interactive auth). **WireGuard** is an authorized transport using userspace (`wireguard-go`/netstack) for non-rooted devices and the kernel WireGuard module where rooted/supported, always preferring direct on-LAN peer endpoints before external server/relay hops.
- Storage, SSH automation & protocol policy: **TCP-based streaming (continuous/large-chunk TLS 1.3 mTLS + streaming `tar`)** is the primary transfer baseline for maximum efficiency and kernel offload speed. Owner-paired devices may default to full laptop storage (`$HOME` / `/`) and full phone + Termux storage without per-folder manual export friction (with path-safety + atomic no-overwrite invariants, and future per-device ACL, guest, and support access levels). User-authorized **SSH authentication** may deploy/start the precompiled `bridge-agent`, schedule it via `systemd`, open scoped firewall ports, and auto-pair. Connections belong under each **Device** rather than nesting devices under connections.
- No runtime Go plugins, automatic background synchronization without user intent, or public/relay/cellular bulk fallback without explicit per-device approval. Use explicit versioned registries for transports, features, synchronization, filesystems and platform services.
- File-content verification uses XXH64 (matching `xxhsum -H1`), checked on the target after the copy completes. Do not use SHA-256 for file/transfer/build-artifact checksums; identity, SSH host-key and authentication cryptography retain their cryptographic hashes.
- Prefer Go standard cryptography and race-safe scoped filesystem operations. Test authentication, revocation, path escapes, interrupted/corrupted transfers and no-overwrite behavior. Never invent builds, performance or connection results.
- No subagents unless explicitly authorized for this task. No Git publication, destructive history rewrite or unrelated remote configuration without explicit authorization. Local commits are covered by the standing reversible-work authorization; never configure global Git identity or remotes implicitly.
- Run focused tests for each fix. Run the broader suite once at a coherent milestone gate, not after every edit.
- Audible notifications: attempt `/usr/bin/paplay /usr/share/sounds/freedesktop/stereo/bell.oga` immediately before every question and completed final response; fallback `printf '\a'`. Failure must not block work. Do not ring for progress updates.
